# Baek（2026 年 8 月）方法在 AHD4Inventory 上的对照实验方案

日期：2026-09-15。状态：**用户已批准第一轮实验，要求先核实模型和费用。** OpenRouter 已通过 `openai/gpt-5.6-sol` 的 Responses 工具调用往返检查。执行记录位于 `output/baek_comparison/20260915_first_round/`；首轮总模型费用上限设为 30 美元，含连接检查与缺陷补跑，触及上限则停止并报告未完成项。

## 1. 实验要回答的问题

在我们实际的库存环境里，按 Jackie Baek 的单任务、可调用 Python 的策略设计流程，frontier LLM 能得到多好的可执行 stationary policy？

第一轮回答三个问题：

1. 每个场景单独设计的策略，成本是否优于现有 AHD 策略与经典基线？
2. 只看需求分布类别和参数范围写出的通用设计程序，能否在不同场景生成好策略？
3. 成绩是否能在独立生成重复、独立需求路径以及较长运行时间下保持？

第一轮是性能对照。历史 AHD 与新实验可能使用不同模型、信息和计算预算，不能据此单独归因于搜索框架。

## 2. 文献与复现边界

确认论文为 Jackie Baek, *LLMs Can Design Near-Optimal OR Algorithms*, arXiv:2608.27296v1，2026-08-27。

- Level 1：给一个具体问题的参数，返回该问题的策略。
- Level 2：给问题类别及宽参数范围，返回 `design(params) -> policy`，程序冻结后才接触评测场景参数。
- 一次 query 是完整工具会话，允许模型自己模拟、检查、修改程序。每次库存 query 的 Python 执行额度为 3600 秒，最多 50 次调用。
- 主流程不给策略提示或检索工具；提交后的程序不能调用 LLM。实例初始化的 30 秒是目标，原代码使用 600 秒防卡死上限并记录实际用时。

依据：[论文方法及附录](https://arxiv.org/html/2608.27296v1)、[原始运行器](https://anonymous.4open.science/r/llm-or-algorithms-F9F2/inventory_lost_sales/run_l2.py)。

公开仓库已经加入 2026 年 9 月数值修正，包含保留全部到货库存、成本和传统基线调参修正。应同时记录论文版本、下载代码的哈希以及 `unbounded-stock-v2` 评测标识，避免混用历史分数。见 [修正记录](https://anonymous.4open.science/r/llm-or-algorithms-F9F2/NUMERICAL_CORRECTIONS.md)。本实验使用我们自己的统一模拟器评分。

原始 Sol L2 策略的需求模型硬编码为 Poisson。它可供策略结构分析，但不能直接作为 Exponential 或 Normal 场景的原样复现。主实验复现的是设计流程，并将问题描述替换为我们的实际环境；不会把作者的最终策略代码或其结构提示交给生成模型。

## 3. 固定我们的环境

### 3.1 数据和动态

| 项目 | 第一轮采用的定义 |
|---|---|
| 需求 | Poisson；四舍五入后的 Exponential；先截零再四舍五入的 Normal |
| 名义均值 | 100；截零/取整后的实际均值以分布定义为准 |
| Normal 标准差 | 10、30、50 |
| 提前期 | 2、4、6 |
| 成本 | holding h=1；lost-sales p=2 或 5；无订货成本 |
| 完整数据网格 | 5 种需求配置 × 3 个提前期 × 2 个罚损成本，共 30 场景 |
| 初始状态 | 现货和在途订单全部为零 |
| 轨迹 | 先运行 L 个零需求备货期，然后运行 50 个销售期 |
| 主评分 | 50 个销售期总成本的路径平均值；同时列每期成本 |
| 策略 | stationary；只能依赖当前现货、在途订单和固定场景参数 |

备货期不是随机需求的稳态预热。策略没有时间索引、剩余期数、未来需求、调用计数器或跨期隐含记忆；不会允许通过识别最后一期停止下单。

运行时策略收到 **本期到货后的现货**，以及 **长度 L−1、按到货先后排列的在途订单**。当前订单在 L 期后到货。例：L=2 时，策略看到一个下一期到货的旧订单；本期新下的订单在两期后到货。

现有 v2 提示词在此处与模拟器不一致。新描述将严格依照实际动态，不直接复用旧提示词的这部分文字。

### 3.2 动作口径

现有主模拟器没有固定订货容量，也不统一取整；后续 best5 评测器接受非负实数动作。为保留现有策略的实际行为，主对照统一接受**非负有限实数订单、无外加容量上限**，整数订单也有效。这是相对于原论文整数、有容量动作空间的明确适配。第一轮要求确定性的 stationary 状态到动作规则，以对齐现有 AHD 策略类；原论文允许随机策略，这一限制会在结果中列为协议差异。

另外报告所有方法在统一整数取整后的敏感性结果。不会只对 Baek 策略增加订单上限或进行取整。非法动作、异常、超时和非平稳策略单独记录，不用静默改成零订单来制造有效成绩。

## 4. 第一轮范围：18 个独立 LLM 会话

当前主运行配置集中在三个场景：

- `poisson_L6_c1_2`
- `normal_std30_L6_c1_2`
- `exponential_L6_c1_2`

| 实验组 | 输入与产物 | 独立重复 | 主要评分范围 |
|---|---|---:|---|
| Baek-L1 | 每个核心场景的精确分布、参数、动态和目标；输出一个 stationary policy | 3 场景 × 3 次 = 9 会话 | 3 个核心场景 |
| Baek-L2 | 分别描述 Poisson、Normal、Exponential 三个问题类别；输出通用 design 程序 | 3 类别 × 3 次 = 9 会话 | 全部 30 场景 |
| 历史 AHD | 审核并冻结现有训练集选出的策略，重新评分 | 保留实际模型、配置和重复标识 | 有可核验策略的场景 |
| 经典基线 | base-stock、constant-order、capped base-stock，重新用训练数据调参 | 固定预先登记的调参流程 | 全部 30 场景 |

Normal 的 10、30、50 三个标准差属于同一个 Level-2 问题类别，不为每个标准差重新询问 LLM。9 个 L2 设计器总共构建 90 个场景策略。

L2 只给宽范围，例如 L 在 [2,10]、名义均值在 [50,150]、h=1、p 在 [2,10]，Normal 的标准差在 [10,100]；不给 30 个测试场景的清单、测试数据、现有策略、基线成绩或人工筛选的示例。T=50 和备货期规则是共同问题定义。程序冻结后，允许 design 用自己的代码针对输入参数模拟和调参，这正是 L2 的含义。

第一轮不会额外做“单一设计器跨三种需求类别”的更宽问题类，避免类别过宽成为额外混杂因素。

## 5. 模型、提示词与运行约束

### 5.1 模型与预算

- 优先使用作者实验的 `gpt-5.6-sol`，L1、L2 均采用 `high` 推理强度；保存实际返回的模型标识。
- 按公开运行器设置，L1 每次 API 调用最多 16384 输出 token，L2 最多 32768；这些数值不是整个会话的总 token 预算。
- 每个会话最多 3600 秒累计 Python 执行、50 次工具调用；LLM 推理和网络等待单独记录。
- 使用标准库、NumPy、SciPy。生成会话只能接触题目与隔离的 Python 工具；不能读取我们的历史策略、测试文件或文献。
- 30 秒实例构建目标、600 秒防卡死上限；逐次报告超过 30 秒的情形，结果中标明时间条件。
- 最终每期策略调用应轻量，不能再调用 LLM；初始化、每期动作和评分耗时分开计量。

18 个计划内首试会话对应 **最多 18 小时 Python 执行额度**。若全部触发下述一次缺陷重试，最坏上限为 36 个会话、36 小时 Python 执行；重试资源单列。两者都不是预计总墙钟时间，也不包括统一评分。原方法可以提前结束；不为了耗尽额度而增加人工追问。API 金额取决于实际可用渠道、token 用量和计费，不在接口核实前虚报固定价格。

接口已核实可用。若后续原模型无法使用，不将其他模型伪装成原模型复现；替代模型需明确标注并由用户选择。

### 5.2 冻结的提示词内容

每条提示只包含：

1. 需求过程的精确定义，包括取整与截零。
2. 到货—决策—需求—成本的事件顺序和接口说明。
3. 50 期销售目标、L 个备货期和 stationary 限制。
4. L1 的具体参数，或 L2 的宽范围。
5. Python 工具、执行额度、可用库和输出格式。

**不预先指定 base-stock、投影库存、均值方差修正、参数个数或某一种优化器。** 模型需要自己选择表示和算法；我们不会再套用 AHD 外层进化流程或外部调参器提高其提交成绩。

输出合同：L1 提交能适配 `compute_order_amount(on_hand_inventory, pipeline_orders)` 的策略；L2 提交 `design(params)`，返回同样接口的策略。参数预处理必须在初始化中完成；状态到动作的映射不得携带跨调用状态。

### 5.3 重复与无效输出

3 次独立会话使用相同提示和预算。主报告列第一份有效输出和全部独立重复的分布，不能按测试成本挑选最好的一次代替该方法的代表成绩。

保留无效原始输出。初步采用最多一次同提示重试的操作上限，作为相对于作者缺陷重试机制的明确实现约定；记录首试成功率、重试次数和总资源，不对有效但较差的策略重跑。

## 6. 统一评分、数据隔离与比较公平性

### 6.1 数据

- 冻结现有 JSON 文件并记录哈希。旧数据没有可恢复的固定生成种子，不编造种子。
- 经典基线用现有前 50 条训练轨迹调参；历史 AHD 根据可追溯训练分数和预先固定的候选范围选取。
- Baek 主组保留原方法的已知分布信息，允许在预算内自行生成模拟样本。因此它与只看 50 条轨迹的历史 AHD 是不同信息条件，结果中明确标注。
- 所有冻结策略在每场景相同的 1000 条测试轨迹上重新评分。既有测试数据曾被旧搜索过程评分，因此称为“现有基准测试集”，不宣称它对整个历史研究过程从未可见。
- 为验证新鲜样本表现，再预先固定种子生成独立测试路径；这些路径在策略冻结后才开放给评分器。若展示从 3 次输出中挑出的最强可交付策略，另设独立验证集先选择，再打开新测试集，报告为额外的三选一结果。
- 新对照运行器的生成和调参阶段不会加载或回传测试成本。旧 `evaluateGreedy()` 会自动评分测试数据，不能原样作为生成反馈工具使用。

### 6.2 历史结果的处理

仓库的现有策略覆盖和选择方式不完全统一：非旧目录的第 10 代最终记录可确认覆盖 20/30 个场景，不能承诺完整 30 场景的同配置 AHD 对照。

只对可核验代码及选择依据的场景报告 AHD 差距；其余列缺失原因，仍报告 Baek 与经典基线。不同历史模型及搜索预算分列，必要时另列“历史最佳现有策略”参考，不混称单一模型的 AHD 成绩。

已有部分传统基线脚本分别在 train 和 test 上找最优参数；这些 test 调参值不能作为本轮可部署基线。必须训练调参、冻结、测试一次。已有跨场景脚本也可能自动重调参数，不能称为直接迁移。

### 6.3 指标

主表每行是一个场景，每种方法列：

- 平均 50 期总成本、每期成本。
- 持有成本、缺货成本、需求满足率。
- 相对训练选定经典基线的成本改善百分比。
- 有历史 AHD 时，相对 AHD 的改善百分比。
- 同一路径上的成本差及其配对 95% 置信区间。
- 3 次生成的各自结果、均值、离散程度和失败率。
- 模型调用数、token、Python 用时、初始化时间、动作时间和实际费用。

统一使用：

`improvement = 100 * (reference_cost - candidate_cost) / reference_cost`

正数代表候选策略成本更低。跨场景总结先求各场景百分比，再做等权平均，避免高成本分布支配总分。生成重复的变异与需求路径的抽样误差分开报告。

同时报告显著胜/负，以及描述性的 0.1%、1% 以内场景比例。没有可靠最优解的场景只称“相对基线差距”，不称 optimality gap；现有 `compute_opt.py` 实际包含策略参数搜索，不能仅凭文件名视为最优解。

### 6.4 长期与整数动作检查

对核心三场景的冻结策略另外使用新种子的长期需求：初步 20 条独立路径、每条 10000 期、丢弃前 2000 期，报告剩余时期的平均成本与配对区间。此项回答已得到的 50 期策略是否能持续运行，不再据此调参。若预先约定的分段稳定性检查显示尚未稳定，应报告该局限，不能选择性为某一方法更换预热长度。

整数动作敏感性对所有方法使用同一规则另列。两项结果均与主任务成绩分开，不改变主要优化目标。

## 7. 实施顺序与交付物

批准后的执行顺序：

1. 固定配置、文件哈希、模型接口和提示；建立独立目录及生成/评分隔离。
2. 用可手算的短轨迹检查订单到货时点、备货期、成本累加和动作合法性；对现有已知策略核对新旧模拟器的一致性。
3. 运行 9 个 L1 会话、9 个 L2 会话；保存提示、最终源码、工具输出、计时、用量、可用推理摘要和失败记录。
4. 冻结源码；构建 L2 的场景策略；冻结经典基线和历史 AHD 选择。
5. 统一评分、独立需求复核、长期和整数动作检查；做配对统计。
6. 给出结果表、逐场景图、可运行策略文件和策略结构说明。解释最强输出实际使用哪些状态量、如何调参、在哪些场景失败。

新内容放在专门的 Baek 对照目录，不覆写历史运行结果。已增加独立的 Responses 工具会话运行器、操作系统隔离的 Python 执行器、严格评分器和可恢复的费用记录；现有历史运行器不参与新生成。

## 8. 第一轮之后的扩展（本次不默认启动）

- **补全 L1 网格：** 剩余 27 场景 × 3 次 = 81 个追加会话。
- **框架归因：** 相同模型、相同分布信息、相同需求样本权限下运行 AHD 和 Baek；分别控制或报告 token 与模拟计算预算。
- **仅样本信息版本：** 将 Baek 也限制为 50 条训练轨迹，单独判断信息优势的贡献。
- **更多重复：** 核心结论需要更稳定时，将独立生成从 3 次增加至 10 次。
- **原作者策略迁移：** 以原始 Poisson 源码为独立诊断组，所有适配另行标注；不与重新生成的 Baek 方法混称。
