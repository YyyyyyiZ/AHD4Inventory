## 配对方向、整数动作与长时域

保存的成本差定义为 **Baek − 对照**，负值有利于 Baek；改善率和改善区间则正值有利于 Baek。134 个已保存配对的需求哈希与协议一致，区间方向及显著性标签相符。当前这些配对均标记为 win，但共享生成器或场景的比较不是独立的 LLM 重复试验。

整数动作检查采用**现有基准测试集的相同需求**，各方法统一 ties-to-even 取整；它不是独立新需求上的第二次检验。检查记录中的 `integer_orders` 标志与批次相符。

长时域检查仅针对三个核心场景；当前完成两个。每场景 20 条路径，每条模拟 10,000 期，丢弃前 2,000 期；保存的总成本对应余下 **8,000 期**，不能与 50 期总成本直接比较。每期成本为：

## 资源文案与必要修正

1. 在跨场景说明中明确：最后一列是 Baek 有效性覆盖，不是相对于该对照的配对数；不同对照可能使用不同场景子集。只补说明，保留现有统计规则。
2. `sandbox.py` 使用 `time.monotonic()` 记录子进程启动到返回的墙钟时间，**不是 CPU 秒数**。本轮生成端至多 3 个 worker、自动评分端至多 2 个 worker 可同时运行，每个 worker 的 BLAS 设为单线程。manifest 记录 OS 和逻辑 CPU 数，但没有记录这一并发配置，故资源部分补充实际配置。预算只能解释为这台机器与该调度条件下的限制，不能作为跨硬件严格相等的计算量。
3. 本快照尚未显示源文件已有的暂停恢复说明；下一次自动生成应纳入。已有两个 Python 进程保留内存后继续执行，未重跑；待返回的 HTTP 响应被保存，未重发请求。日志墙钟跨度包括用户暂停，计费的 Python 执行时间已排除暂停，暂停前的有效时长有亚秒级估计误差；这些恢复不增加独立生成或补跑次数。
